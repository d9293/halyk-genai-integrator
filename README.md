# Integrator.Api

Center of the BPM ↔ AI integration. BPM registers long-running AI tasks and
reads their state; the workers claim work from it and report back. It holds
all state in PostgreSQL and makes every decision (AI limit, retries, lost
tasks, results). Spec: `Final Requirements/Integrator.Api`.

- **BPM API** `/api/v1`: `POST /tasks` (register), `GET /tasks/{requestGuid}` (state)
- **Worker API** `/internal/v1`, used by
  [worker.Request](https://github.com/d9293/halyk-genai-worker-request) and
  [worker.Response](https://github.com/d9293/halyk-genai-worker-response):
  `documents` (copy to S3), `submissions` (send to AI, at most `AI_MAX_IN_FLIGHT`
  at once), `polls` (AI status checks), `results` (Kafka messages for BPM)

Not yet: auth, tracing, metrics, admin panel.

**Running all four apps together:** [docs/local-run.md](docs/local-run.md).

## Run

Needs the local infra Postgres with the project's database and tables; run the
scripts in [scripts/](scripts/README.md) once.

```sh
make run                          # go run . --config_file dev.env
```

- Swagger UI: http://localhost:8080/swagger/index.html (`SWAGGER_ENABLED=true`)
- Liveness: http://localhost:8080/health/liveness (never checks the database)
- Readiness: http://localhost:8080/health/readiness (503 while the database is unreachable)
- Sample requests: `api.http`

`--config_file` is required. The file is loaded into the environment;
variables already set in the environment take priority.

## Docker

```sh
make docker   # builds halyk-genai-integrator:local
docker run -p 8080:8080 -v $PWD/my.env:/config/app.env:ro -e POSTGRES_PASSWORD=… halyk-genai-integrator:local
```

The image holds only the binary (distroless, non-root, no shell); no config is
baked in, `*.env` files stay out of the build. Mount the env file at
`/config/app.env` (or pass another path with `--config_file`) and give secrets
as environment variables, which win over the file.

The image does not run database migrations.

## Develop

```sh
make test              # unit tests; integration tests are skipped
make test-integration  # all tests, incl. integration tests against a throwaway Postgres in Docker
make db-init           # create schema and tables on the local infra Postgres (once)
make minio-init        # sample documents and reports in the local MinIO (bpm-bucket); safe to rerun
make swagger    # regenerate docs/swagger after changing handler annotations (needs swag CLI)
make mocks      # regenerate moq mocks (needs moq)
```

## Layout

```
main.go                       flags, config, signal handling
internal/app                  wiring and HTTP server lifecycle
internal/config               the only package that reads configuration
internal/domain               Task, Document, statuses
internal/usecase/task         registration rules, operation registry, idempotency
internal/usecase/document     document claims for copying to S3
internal/usecase/submission   submission claims, AI limit, outcomes
internal/usecase/poll         status-check claims, observations, lost-task rule
internal/usecase/result       Kafka message claims and delivery
internal/repository/postgres  connection pool and one file per area, with integration tests
internal/handler/http         gin router; one package per area (DTOs, error mapping); httpx shared helpers
docs/swagger                  generated by `make swagger`
schema/postgresql/migration   numbered migrations; `make sql-scripts` builds scripts/ from them
scripts/                      SQL to create the schema and tables; minio/ sample files
```
